# بروتوكول التجربة الميدانية والاحتفاظ — المرحلة الرابعة (Phase 4a & 4b)

> **الشرط المسبق:** إتمام المرحلة 3 وتحديد شريحة ICP واحدة، وتوزيع النسخة المحلية النظيفة (`ENABLE_QA_PREVIEW=false`، بدون أزرار OAuth وهمية، وبوابة `Confirm-Before-Write` مفعّلة).

---

## 1. المرحلة 4أ — تجربة جودة الحلقة الأساسية (أسبوعان | 30–50 مستخدمًا من الـ ICP)

### خطوات التشغيل
1. يثبّت المشارك النسخة المحلية النظيفة.
2. اختياريًا وبموافقة صريحة: يفتح المشارك **الإعدادات ← الخصوصية ← مقاييس جودة المساعد (مجهولة ومغلقة افتراضيًا)**، يفعّل المفتاح، ويختار فئته المجهولة (`طالب / مستقل / موظف / أخرى`).
3. في نهاية الأسبوع الأول والثاني، يضغط المشارك **«تصدير ملخص المقاييس المجهول (JSON)»** ويبعث الملف المجهول فقط (لا يحتوي على أي نصوص مهام أو محادثات أو إيميل أو `userId`).
4. تُجمع الملفات في مجلد واحد (مثلًا `pilot_exports/week2/`) ويُشغّل المقيّم الآلي:
   ```bash
   dart run tool/evaluate_pilot_cohorts.dart pilot_exports/week2 --as-of=2026-12-15 --min-users=30
   ```

### معايير النجاح والإيقاف في 4أ
* **الاستمرار (Go إلى 4ب):**
  - `0` أفعال كتابة أو حذف غير مؤكدة (`Zero-Unconfirmed-Write`).
  - معدل فشل/رفض المنبّهات (`permissionDenied + failed`) منخفض ومعالج بوضوح دون أي فشل صامت.
  - معدل تعديل المسودات (`editRate`) ≤ `35%`، وتأكيد المسودات مرتفع، ودقة الحقول الحرجة (العنوان/التاريخ/الوقت) في عينة أخطاء الميدان ≥ `95%`.
* **الإيقاف/الإصلاح (Stop & Fix):**
  - أي خطأ تدميري أو تذكير فشل صامتًا → إيقاف التوسع فورًا وإصلاح السبب الجذري ثم إعادة جولة تحقق.
  - إذا لم تتحقق عتبة الدقة بعد جولتي إصلاح → **لا توسّع ميزات ولا تنتقل للتسويق**.

## 2. المرحلة 4ب — تجربة الاحتفاظ والنتيجة الفعلية (6–8 أسابيع | 50–100 مستخدم مفعّل من قناة واحدة)

### ما يقيسه المقيّم الآلي (`tool/evaluate_pilot_cohorts.dart`)
* **التفعيل الحقيقي (Activation):** نسبة من اعتمدوا مهمة/تذكيرًا واحدًا على الأقل (`tasksCreated > 0`).
* **الاحتفاظ الحقيقي بحساب Right-Censored (D1 / D7 / D28):** يُحسب فقط على المستخدمين الذين مرّ على يوم تفعيلهم الأول (`firstActivatedAt`) يوم / 7 أيام / 28 يومًا على الأقل حتى تاريخ `--as-of`.
* **العودة الأسبوعية:** نسبة المستخدمين النشطين في أسبوعين مختلفين على الأقل (`distinctActiveWeeks >= 2`).
* **نسبة إنجاز الالتزامات الفعلية (`tasksCompleted / tasksCreated`)** ومقارنتها بخط الأساس (`baselineCompletionRate`) لحساب التحسن النسبي (`relativeCompletionLift`).
* **بوابة الخصوصية الآلية:** أي ملف يحتوي على حقل محظور (`email`, `userId`, `title`, `content`, `tasks`...) أو لا يحمل `consentGranted: true` يُرفض تلقائيًا ويظهر في التقرير.

### قرار البوابة التلقائي للمجلس
| القرار | الشرط | الإجراء الإلزامي |
|---|---|---|
| `go` | `D28 >= 25%` من المفعّلين المؤهلين + تحسن نسبي في الإتمام `>= +20%` مقابل خط الأساس + معدل مشاكل منبّه ≤ `10%` | فتح المرحلة 5 (تفعيل Google Play Billing وقناة اكتساب واحدة) |
| `cautionIterate` | `10% <= D28 < 25%` أو تحسن الإتمام `< +20%` أو `editRate > 35%` | جولة تحسين موجهة في التفعيل أو الـ NLU دون إنفاق إعلاني |
| `stopOrPivot` | `D28 < 10%` أو معدل مشاكل المنبّه `> 10%` | إيقاف التوسع المدفوع فورًا وإعادة تقييم المشكلة/الشريحة |
| `insufficientData` | عدد المفعّلين أو مؤهلي D28 أقل من الحد الأدنى | استكمال جمع البيانات — ممنوع إعلان PMF مبكرًا |
